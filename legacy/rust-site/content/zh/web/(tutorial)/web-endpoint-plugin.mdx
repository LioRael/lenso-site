本步骤生成 `company.greetings-http`，它提供两条
`lenso.http.endpoint@1` Route。完成本步骤后再连接 Ingress。

| Operation | HTTP Method | Path |
| --- | --- | --- |
| `greetings.create` | `POST` | `/greetings` |
| `greetings.search` | `QUERY` | `/greetings/search` |

## 1. 生成 Plugin

先按 [Plugin 快速开始](/docs/zh/core/quickstart)安装 CLI，再进入 Web 编写路径。
下面的目录由 npm `@lenso/cli@0.17.4` 对应的原生 CLI `0.6.4` 生成：

```sh
lenso plugin new company.greetings-http --web
cd company.greetings-http
```

该命令会创建一个独立的 Linked Rust Plugin：

```text
company.greetings-http/
├── Cargo.toml
├── build.rs
├── README.md
└── src/
    ├── lib.rs
    └── routes/
        ├── create.rs
        └── search.rs
```

Manifest 已经声明 Web Root Slot，并固定相互兼容的 Framework Revision：

```toml title="Cargo.toml"
[package.metadata.lenso]
plugin-id = "company.greetings-http"
root-slot = "web"
```

默认情况下，生成流程还会创建 `Cargo.lock` 并运行无 Socket 测试。仅当依赖必须
稍后解析时才使用 `--no-install`。把 Crate 移入 Host Workspace 时，改用该
Workspace 的 Dependency Entry，并删除脚手架中用于隔离独立项目的
`[workspace]` Table。如果复制、重命名脚手架或修改 Manifest，先在对应
Crate 或 Workspace 根目录运行 `cargo generate-lockfile` 更新受影响的
`Cargo.lock`，再执行 `cargo test --locked` 或 `lenso app build`。过期的
Lockfile 会在构建的 Cargo Metadata 锁定检查中失败。

## 2. 实现 Route

保留生成的 `src/lib.rs`、`build.rs` 与 `src/routes/create.rs`。
Create 的 `#[post("greetings.create", "/greetings")]` Attribute 保持不变。
`src/lib.rs` 持有共享请求/响应类型与 `GreetingsHttp` 状态；`src/routes/`
中的每个文件包含一个 Handler。Build Script 将它们合并为 `#[endpoint]`
实现，再由 `src/lib.rs` 引入。不要另外添加内联实现，也不要删除生成的 include。

脚手架最初对两条路由都使用 **POST**。本教程有意将搜索改为 **QUERY**。
在 `src/routes/search.rs` 中只修改第一个 Attribute，保留 Handler 及其他 Attribute：

```diff title="src/routes/search.rs"
-#[post("greetings.search", "/greetings/search")]
+#[query("greetings.search", "/greetings/search")]
```

生成的 Create Handler 保存问候并返回 `201`；Search Handler 返回匹配的问候。
两者都用 `400` Problem 拒绝空输入。现有测试按 Operation ID 调用，因此搜索方法
改变后仍然适用。重新构建后，再执行[证明 HTTP 后端](/docs/zh/web/web-testing)
中的 QUERY 请求。

`#[lenso::plugin]` 声明产品行为边界；`#[endpoint]` 从同一组声明生成 Route
Description、Dispatch Path、`lenso.http.endpoint@1` Capability 与 Linked Plugin
Factory。业务作者不需要实现 `NativePluginFactory`，更不应再编写
`NativeModuleFactory`。Handler 直接返回面向业务的值：`Json<T>` 表示 `200`
JSON Response，`(StatusCode, T)` 覆盖状态码，`Problem` 表示有意返回给 Client
的失败；Macro 会把它们降为 Portable Capability Contract。Handler 返回类型应写成
`Result<Json<T>, Problem>`，列表操作也一样。无响应 Body 的删除操作使用
`Result<HandleResponse, Problem>`，返回
`Ok(lenso_capability_http_endpoint::response::empty(StatusCode::NO_CONTENT))`。

`Json<T>` 也会在 Handler 运行前拒绝无效 JSON 与不支持的 Content Type，
`Path<T>` 解码命名 Path Parameter，`QueryParams<T>` 解码 URL Query String。
HTTP QUERY Method 使用 `#[query("route.id", "/path")]`：它适合安全、幂等、
但需要结构化 Body 的请求，和 URL Query Parameter 不是一回事。

示例中的 Map 是临时 Instance State。其他 Interface 也需要 Greeting 行为时，
把共享业务 Fact 移到业务 Capability Provider。持久状态属于 Store Plugin，
不属于 Ingress。

## 3. 直接证明 Provider

脚手架的 `src/lib.rs` 已有无 Socket 的 `tests` 模块。把下面的函数加入该模块，
保留已有 Import 和生成的失败路径测试：

```rust title="src/lib.rs — inside mod tests"
#[test]
fn finds_the_created_greeting() {
    block_on(async {
        let endpoint = EndpointTest::new(GreetingsHttp::default());
        let created = endpoint
            .request("greetings.create")
            .json(&CreateGreeting {
                name: "Lenso".to_owned(),
            })
            .unwrap()
            .send()
            .await
            .unwrap();
        assert_eq!(created.status(), StatusCode::CREATED);
        let found = endpoint
            .request("greetings.search")
            .json(&SearchGreetings {
                term: "Lenso".to_owned(),
            })
            .unwrap()
            .send()
            .await
            .unwrap();
        assert_eq!(found.json::<Vec<Greeting>>().unwrap().len(), 1);
    });
}
```

`EndpointTest` 从生成的 Route Table 读取 Method 与 Path，直接调用 Plugin，
因此无需绑定端口即可测试 Extractor、Middleware、Typed Response 与 Dispatch。
Request Builder 还支持 `.query()`、`.path_parameter()` 与 `.header()`。

针对生成的 `EndpointProvider` 增加聚焦测试：

- `describe` 只返回 `greetings.create` 和 `greetings.search`；
- 有效 JSON 返回 `201`；
- 空 `name` 返回有意设计的 `400` Problem Details；
- 无效 JSON 与不支持的 Content Type 在 `create` 前失败；
- `greetings.search` 使用 HTTP QUERY Method 并接收 JSON Body。

运行 Crate 检查：

```sh
cargo fmt --all
cargo fmt --all -- --check
cargo test --locked
cargo clippy --locked --all-targets -- -D warnings
```

Owner Repository 的 `examples/greetings-http-plugin` 是完整的内联 Endpoint
示例，其布局与上面的路由文件脚手架不同。仓库也维护了 Extractor 与 Response 示例：

```sh
cargo test --locked -p lenso-capability-http-endpoint \
  --test endpoint_attributes
```

当 `POST /greetings` 与 `QUERY /greetings/search` 的 Route Description 稳定，并且所有直接成功与失败断言通过时，本步骤完成。继续
[连接 Host 与 Ingress](/docs/zh/web/web-host-integration)。
