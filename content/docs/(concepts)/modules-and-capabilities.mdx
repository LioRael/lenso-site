---
title: Modules and Capabilities
description: Model product behavior as installable Modules connected through versioned deep role Interfaces.
---

## Module

A Module is an installable product capability with one authoring Interface. A
Plan may instantiate the same Module package more than once; each Module
Instance has an App-local key, lifecycle generation, configuration, endpoints,
and bindings.

## Capability

A Capability is a versioned deep role Interface. It owns stable Operations and
their domain values, not transport, deployment, or a particular implementation.
Consumers receive only the typed handles explicitly bound by Composition.

Operations have three interaction shapes:

- **Request** — one terminal result;
- **Stream** — bidirectional flow with bounded buffering, independent
  half-close, cancellation, and an explicit terminal result;
- **Event** — volatile fan-out with independent bounded admission and partial
  outcomes, never implied persistence or redelivery.

## Binding cardinality

Requirements declare exactly-one, optional-one, or many providers. Resolution
checks cardinality before boot. The Kernel does not choose a fallback provider,
rebind after startup, or discover a new implementation.

## Domain and runtime failures

Expected domain outcomes stay in the generated Capability contract. Runtime
failures describe admission, deadlines, cancellation, provider failure, invalid
wire values, or unavailable execution. Keeping the two separate makes retry and
authorization policy explicit at the caller.
