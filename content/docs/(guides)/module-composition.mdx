---
title: App definitions
description: Select Module packages and keyed Instances without hand-authoring the derived Composition.
---

A Module package owns its generated Descriptor: provided Capabilities, Ports,
Operations, execution class, configuration Schema, and lifecycle facts. An App
Definition owns only App intent: selected packages, keyed Instances,
configuration, lanes, and decisions for real provider ambiguity.

## Write intent, not the graph

```json title="lenso.app.json"
{
  "schema_version": 1,
  "manifest": "Cargo.toml",
  "packages": {
    "example.orders": "orders-module",
    "lenso.secrets.env": "lenso-secrets-env-module",
    "lenso.web-ingress": "lenso-web-ingress"
  },
  "app": {
    "name": "orders",
    "modules": [
      { "key": "orders", "package": "example.orders" },
      {
        "key": "secrets",
        "package": "lenso.secrets.env",
        "configuration": {
          "references": { "database/url": "APP_DATABASE_URL" }
        }
      },
      {
        "key": "web",
        "package": "lenso.web-ingress",
        "configuration": { "bind_address": "0.0.0.0:8080" }
      }
    ],
    "decisions": []
  }
}
```

The resolver reads each locked package-owned Descriptor. If one compatible
provider exists, it closes the binding automatically. `one` ambiguity becomes
an explicit App decision; `many` providers receive deterministic order. A
Module cannot query a global registry for an undeclared dependency.

## Change the App transactionally

```sh
lenso app add orders-module --definition lenso.app.json --version '^1.0' --dry-run
lenso app add orders-module --definition lenso.app.json --version '^1.0'

lenso app check --definition lenso.app.json
lenso app resolve --definition lenso.app.json \
  --output .lenso/resolved-plan.json

lenso app remove orders --definition lenso.app.json --dry-run
lenso app remove orders --definition lenso.app.json --uninstall
```

`app add` and `app remove` edit the package manifest, ordinary lock, and App
Definition as one transaction. `app check` validates the selected locked
packages and derived graph. `app resolve` emits canonical Plan bytes for the
product-owned Runner or Host; there is no generic author-facing `run --plan`
command.

## Put policy in the right owner

| Concern | Owner |
| --- | --- |
| Business rules, migrations, and transactions | Owning Module |
| Interface types and Domain Errors | Capability owner |
| Package selection, configuration, lanes, real ambiguity | App Definition |
| Derived endpoints and bindings | Resolver output |
| Scheduling, cancellation, and shutdown | Runtime Driver and Kernel |
| HTTP, process, browser, or host failure mechanics | Execution Adapter or protocol Module |

Store only logical secret references in configuration. Removing a product
concern should remove its Module selection without changing Kernel. Replacing a
provider produces a new Plan or App Generation, never runtime discovery.
