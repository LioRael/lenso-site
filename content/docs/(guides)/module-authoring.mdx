title: Rust Module authoring
description: Implement a generated Capability Provider and register a statically linked native Module factory.
---

Native Rust Modules implement generated Provider traits and register a factory
with `lenso-native-adapter`. They are statically linked; the runtime does not
scan Cargo packages at boot.

## Implement the generated Provider

Assume the `example.greeting@1` Descriptor from
[Capability authoring](/docs/capability-authoring) generated `GreetingProvider`,
`GreetingEndpoint`, and the request/response/error types:

```rust title="src/lib.rs"
use futures::future;
use lenso_kernel::{InvocationContext, NativeRequestFuture};

use crate::generated::{
    GreetError, GreetRequest, GreetResponse, Greeting, GreetingProvider,
};

#[derive(Debug)]
pub struct Greeter;

impl GreetingProvider for Greeter {
    fn greet(
        &self,
        _context: InvocationContext,
        request: GreetRequest,
    ) -> NativeRequestFuture<Greeting> {
        let result = if request.name.trim().is_empty() {
            Err(GreetError::EmptyName)
        } else {
            Ok(GreetResponse {
                message: format!("Hello, {}!", request.name),
            })
        };
        Box::pin(future::ready(Ok(result)))
    }
}
```

The outer `Result` is a `RuntimeFailure`; the inner `Result` is the generated
Domain Result. Keep validation failures such as `empty_name` in the inner
result.

## Export a Module factory

The factory identity must match the package selected by the Resolved App Plan:

```rust title="src/lib.rs"
use std::rc::Rc;
use lenso_kernel::{NativeRequestEndpoint, RuntimeFailure};
use lenso_native_adapter::{
    NativeModuleFactory, NativeModuleFactoryContext, NativeModuleInstance,
};

use crate::generated::GreetingEndpoint;

#[derive(Debug)]
pub struct GreeterFactory;

impl NativeModuleFactory for GreeterFactory {
    fn package_id(&self) -> &'static str { "example.greeter" }
    fn package_version(&self) -> &'static str { env!("CARGO_PKG_VERSION") }

    fn instantiate(
        &self,
        _context: NativeModuleFactoryContext<'_>,
    ) -> Result<NativeModuleInstance, RuntimeFailure> {
        let endpoint = Rc::new(GreetingEndpoint::new(Greeter))
            as Rc<dyn NativeRequestEndpoint>;
        Ok(NativeModuleInstance::new(vec![endpoint]))
    }
}
```

## Register it in the App binary

```rust
use lenso_native_adapter::NativeModuleRegistry;

let native = NativeModuleRegistry::new()
    .with_factory(example_greeter::GreeterFactory);
```

Pass this registry as the native Execution Adapter when assembling the Kernel
and `TokioDriver`. Registering two factories with the same package identity is
an error; omitting the selected factory produces `MissingModuleFactory`.

:::warning
`lenso check` and `lenso resolve` validate native packages, but the generic CLI
cannot dynamically link an arbitrary Rust factory. A native App binary must
statically register its factories as shown above. `lenso run` is directly
executable for Bun entrypoints; native auto-linking is not implemented.
:::

## Consume a required Capability

Generated clients resolve only explicitly bound dependencies:

```rust
use crate::generated::{GreetRequest, GreetingClient};
use lenso_kernel::{ModuleDependencies, RuntimeFailure};

fn client(dependencies: &ModuleDependencies) -> Result<GreetingClient, RuntimeFailure> {
    GreetingClient::from_dependencies(dependencies)
}

async fn call(client: &GreetingClient) {
    let response = client.greet(GreetRequest { name: "Ada".into() }).await;
    // Match Domain and Runtime failures separately here.
    println!("{response:?}");
}
```

Use `NativeModuleInstance::with_stream_endpoints`, `with_event_endpoints`, or
`with_all_endpoints` for generated Stream and Event endpoints. The maintained
[generated request fixture](https://github.com/LioRael/lenso-cli/blob/main/crates/lenso-authoring/tests/fixtures/contracts/greeting/src/generated.rs)
shows the exact Provider, Endpoint, and Client signatures.
