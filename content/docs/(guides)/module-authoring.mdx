---
title: Rust Module authoring
description: Implement a native Module through Lenso's public Rust facade.
---

A native Module should read like business behavior, not runtime wiring. The
public facade derives its Descriptor, Adapter factory, endpoint registration,
and configuration decoder from the Module source.

## Create a Module

```sh
lenso new greeting --runtime rust
cd greeting
lenso check
lenso dev
lenso verify
```

The scaffold includes a Capability contract, a native Module, a development
Runner, a lock, and verification cases. `lenso dev` rebuilds the selected
package, resolves a fresh App Plan, and restarts the Runner after relevant
source changes.

Use `--recipe stateless`, `stateful`, `web-console`, or `managed-work` to seed a
focused Module card. The card records intent; generated runtime metadata remains
derived from source.

## Implement behavior

Assume [Capability authoring](/docs/capability-authoring) generated the
`greeting_contract` crate:

```rust title="src/lib.rs"
use greeting_contract as greeting;
use lenso::prelude::*;

#[module]
#[derive(Clone, Debug)]
struct Greeter;

#[provides(greeting::Greeting)]
impl Greeter {
    async fn greet(
        &self,
        _context: Ctx,
        request: greeting::GreetRequest,
    ) -> Result<greeting::GreetResponse, greeting::GreetError> {
        if request.name.trim().is_empty() {
            Err(greeting::GreetError::EmptyName)
        } else {
            Ok(greeting::GreetResponse {
                message: format!("Hello, {}!", request.name),
            })
        }
    }
}
```

The method returns the generated Domain Result. Adapter failures remain a
runtime concern handled by generated lowering. You do not implement
`NativeModuleFactory` or register individual endpoints by hand.

## Add configuration only when needed

```rust title="src/lib.rs"
#[derive(Clone, Debug, serde::Deserialize)]
#[serde(deny_unknown_fields)]
struct GreetingConfig {
    prefix: String,
}

#[module]
#[derive(Clone, Debug)]
struct Greeter {
    #[config]
    config: GreetingConfig,
}
```

Stateless Modules omit `#[config]`. The generated factory decodes and validates
the selected Instance's configuration when it creates the Module.

## Add lifecycle and dependencies only when needed

Endpoint-only Modules need no lifecycle implementation. Modules that own
resources or managed work opt in explicitly:

```rust title="src/lib.rs"
#[module(lifecycle)]
#[derive(Clone, Debug)]
struct Worker {
    greeting: Port<greeting::GreetingClient>,
}

impl Lifecycle for Worker {
    async fn activate(
        &self,
        context: ActivateContext,
    ) -> Result<(), RuntimeFailure> {
        // Start Module-owned work through context.tasks().
        Ok(())
    }

    async fn deactivate(
        &self,
        context: DeactivateContext,
    ) -> Result<(), RuntimeFailure> {
        // Close Module-owned resources here.
        Ok(())
    }
}
```

Generated glue connects `Port<Client>` fields from the dependencies explicitly
bound in the App Plan. There is no global Capability registry.

## Link it into a product Runner

The product App binary makes all compiled Module factories available once:

```rust
let native = NativeModuleRegistry::new().with_linked_factories();
let adapters = ExecutionAdapterCatalog::single(native);
```

Linking makes a factory available; it does not activate the Module. The App
Definition still selects Instances and bindings, and the product-owned Host
runs the resolved immutable Plan. See [Module composition](/docs/module-composition).

## Check and prove removal

`lenso check` gives fast source, contract, configuration, and package-lock
diagnostics. `lenso verify` runs the declared success, Domain Error, Runtime
Failure, lifecycle, and removal probes and writes
`.lenso/module-verification.json` for CI and agents.
