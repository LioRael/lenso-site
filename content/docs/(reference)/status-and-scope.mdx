This page separates runtime behavior from packaging and ergonomics. “Source
implemented” does not imply that every interaction kind or production App has a
high-level starter.

## Core and authoring

| Area | Works now | Current limitation |
| --- | --- | --- |
| App Plan | canonical validation, explicit Modules, bindings, execution classes, lanes, admission policy | no runtime discovery or graph mutation |
| Kernel | Request, Stream, Event, lifecycle, deadlines, cancellation, diagnostics, deterministic conformance | owns no HTTP, database, Auth, process, or product policy |
| Contract tooling | JSON Descriptor to independently generated Rust or TypeScript, drift check, compatibility lint, portable value runtime | each language artifact must be committed by the package that distributes it |
| `lenso` authoring | `add`, `check`, `resolve`, and `run`; typed Bun scaffold and watch-mode development; Cargo, Bun, npm, and OCI package inputs | Bun starter creates a Module project, not a complete production App |

## Runtime implementations

| Path | Request | Stream | Event | How it runs today |
| --- | --- | --- | --- | --- |
| Native Rust | implemented | implemented | implemented | statically register `NativeModuleFactory` values in the App binary |
| Bun / TypeScript | public typed SDK | Adapter conformance only | Adapter conformance only | `lenso module dev` infers the project and starts entrypoints through `lenso.bun-process@1`; production wire is JSON-RPC over loopback HTTP |
| Browser JavaScript Driver | scheduler/lifecycle smoke evidence | Kernel semantics apply | Kernel semantics apply | host profile; not hostile-code isolation |
| WASIp2 Driver | scheduler/lifecycle smoke evidence | Kernel semantics apply | Kernel semantics apply | host profile; component packaging is not a starter workflow yet |

The Bun path is not an experimental fallback. It has bounded frames and queues,
handshake/session checks, deadline and cancellation propagation, typed
domain/runtime outcomes, process cleanup, and cross-runtime fixtures. The
published `@lenso/bun-module` package owns the Module-side server, and the CLI
creates a complete typed project and fresh-Plan development loop. Version 0.1
exposes Request Providers; Stream and Event remain fail-closed at the public SDK
surface even though the lower-level Adapter has conformance for both.

## Optional Capabilities and Modules

| Component | Implemented source | Packaging / usage boundary |
| --- | --- | --- |
| Auth | `lenso.auth@1`, Rust assertion SDK, PostgreSQL API Token Provider, revocation | API Token Module crate is intentionally private; Bun public verifier helper is missing |
| Secrets | `lenso.secrets@1` and allowlisted environment Provider | registry publication is parked; production cloud Providers are not included |
| Backend Web | HTTP Endpoint/Ingress and HTTP Client/Egress Capabilities and Modules; opt-in OpenAPI 3.1 document Module | maintained providers are linked Rust Modules; OpenAPI requires an explicitly selected Instance and bindings, and includes no UI |
| PostgreSQL Kit | owned-schema setup, upgrade, drift detection, and verified SQLx pool | infrastructure kit, not a shared State Module or cross-Module SQL boundary |
| OpenTelemetry | removable native Module plus Rust/Bun trace propagation fixtures | tracing is optional Composition, never Kernel behavior |
| Web UI | explicit Shell, Browser Adapter, and UI Contribution roles with target-owned composition evidence | not a general remote-code sandbox or independent Console product |

Read [Auth Module](/docs/auth-module) for the exact implemented provider and
missing-provider list. Read [Bun Module authoring](/docs/bun-module-authoring)
for the current executable path rather than inferring support from repository
names. The [Web Capabilities](/docs/web-capabilities),
[Secrets Module](/docs/secrets-module), and [PostgreSQL Kit](/docs/postgres-kit)
guides show the concrete contracts and lifecycle boundaries.

## Not implemented

Lenso does not currently provide runtime discovery, hot graph mutation, rolling
upgrades, distributed placement, automatic replicas, a control plane, hostile
browser-code isolation, an independent Console product, OAuth/password Auth
Providers, or a production cloud Secrets Provider.

Retained vocabulary and architecture seams are not feature evidence. A feature
belongs in the tables above only when an owner repository contains the behavior
and a validation path.
