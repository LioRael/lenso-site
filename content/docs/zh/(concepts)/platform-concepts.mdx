## 核心模型

- Module 是 Host 中的 Linked 业务能力边界。
- Service 是独立运行、拥有进程、Store、交付和终态证据的代码。
- Service 可以声明它提供的 Module，但 Service 本身不是 Module。
- Lenso Console 是独立 System Plane 工作台，不是业务管理后台，也不是 effect authority。

## Manifest 与行为

`ModuleManifest` 是纯数据合约，用来声明能力、路由、管理 Surface、运行时工作、
Console Surface 与依赖。Linked Module 的可执行行为通过窄 Binding 接入。
Service 的行为属于其 Provider API 和 Workload。

## 运行时证据

Host 仍拥有请求身份解析、能力校验、队列、Outbox 与 Host Runtime Story。
Service 拥有 Provider 执行和 Service Store 的终态证据。跨边界传递 correlation、
trace、actor 与 operation identity，不引入分布式事务。

## 拆分原则

默认保持 Linked。只有当独立运行时、部署节奏、团队所有权、Store、扩缩容或信任
边界足以支付分布式系统成本时，才提取 Service。

[Service System Plane](/docs/zh/service-system-plane)。
