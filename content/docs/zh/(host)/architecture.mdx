Lenso 从模块化单体开始。Module 只有一种当前加载来源：Linked。需要独立进程、
运行时、Store、发布节奏或信任边界的代码是 Service；Service 可以通过明确的
Provider 合约提供 Module，但不会成为第二种 Module Source。

## 运行形态

一个生成的 Host 包含 API、Worker、Migration Workload 与 Host Store。
Linked Module 通过组合根进入 Host，并共享 Host 的发布与事务边界。

Lenso Console 是独立的 Operator-facing Service。它通过 System Plane 观察、
规划、审批并聚合证据，但不会取得 Host 或业务 Service 的 effect authority。

## 所有权

| 组件 | 所有权 |
| --- | --- |
| Host | Linked Module 组合、Data Plane、能力校验、Host Store |
| Service | 独立进程、Service Store、Provider API、终态执行证据 |
| Lenso Console | Operator 工作流、计划与证据聚合 |

## Linked Module 或 Service

能力属于同一应用和发布周期时使用 Linked Module。只有在运行时、所有者、部署、
Store 或信任边界真实存在时才提取 Service。

提取后，通过 `lenso service install <service-manifest>` 安装 Provider，并用
`lenso service doctor <provider> --json` 验证健康与漂移。Remote Module
不是当前加载来源或公开包类别。
