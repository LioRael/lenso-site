---
title: Host 快速开始
description: 组合 Support Desk、在本地运行、连接 Console，并检查精确状态。
---

本快速开始完整使用公开 Lenso 生命周期：创建唯一的应用组合，通过 System
Sandbox 在本地运行，把它连接到独立 Console Service，然后检查每个对象的
直接状态。

## 前置条件

- Rust 与 Cargo
- Support Desk Provider 使用的 Node.js 与 pnpm
- 用于本地 Postgres 的 Docker
- 能持续运行本地进程的终端

## 安装 CLI

安装任意一个提供 `lenso` 命令的软件包：

```sh
cargo install lenso-cli
# 或
npm install -g @lenso/cli
```

继续前确认版本：

```sh
lenso --version
```

## 1. Compose（组合）

```sh
lenso app compose ./support-desk --blueprint support-desk --apply
cd support-desk
```

Bare Blueprint 选择 `auth`、`notification-worker` 与 `support-api`。Pack-backed
Support Ticket 与 Story 组合由独立的[产品级验收](/docs/zh/examples)覆盖；该
Runner 还会在本地启动前注册 Service-backed Provider。

检查 `lenso.app.json`。它是精确的应用组合与锁：应用修订与内容摘要、不可变
Module Release 选择、已解析依赖、Implementation Binding 与 Provenance 必须
一致，System 才能启动。

## 2. Run locally（本地运行）

```sh
lenso system dev --system-file lenso.app.json --dry-run --json
lenso system dev --system-file lenso.app.json
```

第二条命令启动声明的应用和持久 Local Control Adapter。完成后使用明确的
清理入口：

```sh
lenso system dev --system-file lenso.app.json --cleanup
```

## 3. Connect（连接）

独立安装或运行 Console Service。以 Console Operator 身份认证后，先把每个
业务 Service 目标已签名的 `{offer, receipt, baseUrl}` 提交到
`POST /api/console/v1/enrollment-receipts`，再把应用的精确
`lenso.system.v2` 拓扑和 Management Binding 提交到：

```text
POST /api/console/v1/system/connect
```

当前本地切片的 Enrollment Endpoint 只接受 loopback 目标，不是远程生产自助
路径。CLI 自有 `lenso-local-control-adapter` 以 `workload-control:<system>`
绑定，不使用业务 Enrollment；其余每个拓扑 Service 都必须具备 active signed
Enrollment。连接请求必须携带所提交拓扑的内容摘要。浏览器代码不会获得 Service 或 Adapter
凭据。Console 只存储连接，不启动、部署、接管或修复应用。

## 4. Status（状态）

打开 Console 并选择 **Services**，或调用：

```text
GET /api/console/v1/system
```

System、Service、Module、Surface 与 Adapter Projection 分别报告连接状态与
原因：`connected`、`unavailable`、`incompatible` 或 `unmanaged`。Workload
Operational State 是独立维度。

对于本地受控 Workload，可执行受支持的 Suspend/Resume 或 Stop/Start 操作。
Console 返回异步 Operation Record，并轮询 Adapter 直到终态。Adapter 无法访问
时，Workload Observation 为 `unknown`，变更会立即被拒绝。

## 添加业务能力

无论 Module 链接到 Host，还是由 Service 提供，它都保持业务身份。先阅读
[Module 开发](/docs/zh/module-authoring)，再根据运维流程的需要，公开强类型
Business API 与回执绑定的 Console Surface。

TypeScript `@lenso/service-kit` 支持 Provider tier。Autonomous Service tier
使用 Rust。准确边界参见
[Service Capability Tiers](/docs/zh/autonomous-services)。
