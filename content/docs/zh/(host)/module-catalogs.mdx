---
title: 模块目录
description: 了解 Lenso 模块发现目录、官方后备条目和安装边界。
---

模块目录是发现数据。它可以帮助操作员找到模块，但它
不安装它们。

这种划分很重要：

- 官方或明确的目录=记住这个模块存在；
- 模块安装=写入主机本地安装状态；
- 主机启动 = 加载配置的链接源和服务/Service Provider。

## 本地目录文件

对于本地发现实验，将 `.env` 指向目录文件：

```env
LENSO_MODULE_CATALOG_FILE=.lenso/module-catalog.json
```

目录条目包含模块名称、版本、发行参考、提供者
服务、基本 URL、摘要、功能和控制台包提示。

## 从目录或 Manifest安装

install命令仍然是改变主机的边界：

```sh
lenso module install support-ticket
```

对于本地发布工件，请传递运行时服务基本 URL：

```sh
lenso module install dist/lenso-service/support-suite-provider/modules/support-ticket/lenso.module-release.json \
  --base-url http://127.0.0.1:4110/lenso/service/v1
```

安装写入主机本地状态，例如 `.env`、安装回执、服务
描述符和控制台扩展注册表文件。看
[该写入集的模块安装](/docs/zh/module-installation)。

## 可用模块顺序

Runtime Console的可用模块视图合并发现源：

1. 显式 `.env` `LENSO_MODULE_CATALOG_FILE=<path>`；
2. 已配置的服务或Service Provider；
3. 内置`builtin:lenso-official-module-catalog`。

内置目录是新主机的默认官方来源。它不是一个
已安装模块的隐藏数据库。

## 目录中的链接模块

第一方链接模块，例如 `auth`、`auth-password` 和 `auth-device`
可以出现在目录中，因为它们是可安装的主机功能。

它们的安装路径与服务支持的模块不同：

```sh
lenso module install auth
lenso module install auth-password
lenso module install auth-device
```

链接安装更新生成的主机的本地组合和模块
设置。服务支持的安装更新Provider源配置和
可选服务或控制台扩展状态。

## 目录条目形态

有用的目录条目回答了操作员的第一个问题：

```json
{
  "name": "support-ticket",
  "version": "0.1.0",
  "protocol": "lenso.module-release.v1",
  "manifestReference": "dist/lenso-service/support-suite-provider/modules/support-ticket/lenso.module-release.json",
  "baseUrl": "http://127.0.0.1:4110/lenso/service/v1",
  "source": "service",
  "providedBy": "support-suite-provider",
  "summary": "Ticket intake, triage, and operations",
  "capabilities": [
    "support_ticket.tickets.read",
    "support_ticket.tickets.write"
  ]
}
```

主机在安装和启动期间仍会验证Manifest。目录
元数据是为了发现，而不是信任。

## 何时使用目录

在以下情况下使用目录：

- 您的团队拥有一组已知的服务支持模块；
- 操作员应在安装之前查看模块；
- 您希望Runtime Console显示精选的安装路径；
- 模块 Manifest URL 足够稳定，可以共享。

测试本地模块时跳过目录。安装发布工件
直接，然后在模块值得发现后添加目录元数据。
