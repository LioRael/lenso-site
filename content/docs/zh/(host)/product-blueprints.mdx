---

产品蓝图是从产品想法到可运行 Lenso System 的最短路径。蓝图创建应用源码
形态，以及选择 Module 的唯一 `lenso.app.json` 组合锁。

## 使用持续维护的蓝图

Support Desk 是持续维护的产品级基础。请直接按名称组合它，不要依赖仅供仓库
开发使用的隐藏检查命令。蓝图本身只选择 `auth`、`notification-worker` 与
`support-api`。

产品验收通过仓库内的 Capability Pack 加入 Support Ticket 与 Story Module
选择。Runner 从 `lenso-examples` 中由 Module 持有的示例包构建精确的 Support
Ticket Console Surface，再通过 Console 协调该 Artifact。

## Compose 基础

```sh
lenso app compose ./support-desk --blueprint support-desk --apply
```

组合会写入 `support-desk/lenso.app.json`。该文件记录：

- 应用协议、身份和单调递增修订；
- 选定的 Blueprint 与 Capability Pack；
- 每个不可变 Module Release 的身份、版本、Owner、内容摘要与 Business
  Contribution；
- 已解析依赖的身份、版本与内容摘要；
- Linked 或 Service-backed Implementation Binding；
- Blueprint 与 Capability Pack Provenance。

组合文件不是进程启动器、凭据文件或生产交付记录。`lenso dev up` 会为本地
开发实现其中选择的 Host 与 Provider。更底层的 `lenso system dev` 仍是用于
隔离 Topology 与 Adapter 检查的 System Sandbox。

## Compose 产品验收

```sh
lenso app compose ./support-desk \
  --blueprint support-desk \
  --pack ./fixtures/acceptance/support-desk/capability \
  --implementation support-api=linked \
  --implementation notification-worker=linked \
  --implementation lenso/platform-story=linked \
  --apply
```

请从 `lenso-examples` 仓库根目录运行该命令。Capability Pack 提供
`support/tickets` Service Delivery 与 `lenso/platform-story`；Implementation Flag
明确本地验收使用的 Binding。启动前，Runner 使用公开的
`lenso service workspace init --force` 与
`lenso service workspace add support-ticket`，把带有 `lenso.service.json` 的
唯一 Service-backed Provider 注册到 App Workspace。

请运行受支持的黑盒路径，不要在缺少该 Workspace Entry 时直接启动这份
Pack-backed 组合：

```sh
pnpm acceptance:support-desk
```

## 在本地运行并连接基础组合

```sh
cd support-desk
lenso dev up --console-root ../lenso-console
```

该命令在同一个前台 Session 中启动 Host、auto-start Provider Service 和现有
Console Checkout，创建已签名的本地连接材料、协调 Module 自有 UI Artifact，
并连接精确拓扑。Ctrl-C 只停止本次调用启动的进程。

只有需要在已连接 Host、Provider 与 Console 路径之外单独校验或运行隔离的
System Shape 时，才使用更底层的 Sandbox：

```sh
lenso system dev --system-file lenso.app.json --dry-run --json
lenso system dev --system-file lenso.app.json
```

使用 `--cleanup` 停止该次 Sandbox Run 持有的资源。

## 使用能力包扩展

能力包是可复用的本地组合输入，可携带 Module、Service、文档与 Agent 上下文：

```sh
lenso capability init support-sla \
  --dir ./capabilities/support-sla \
  --lang ts \
  --for-blueprint support-desk
lenso capability library add ./capabilities/support-sla
lenso capability fit support-sla --repo-root .
lenso app compose --repo-root . --pack support-sla --apply
```

能力包不会安装 Module Release、发布 Service 或变更生产基础设施。重新组合
应用，让每个已接受选择进入新的 `lenso.app.json` 修订。

## 连接并检查状态

Console Service 接收从已组合应用派生的精确 `lenso.system.v2` 拓扑和
Management Binding。连接后，它只加载回执绑定的 Surface，并报告直接对象
状态。Console 不会扩大组合，也不会选择部署目标。

完整四步生命周期参见 [Host 快速开始](/docs/zh/quickstart)；Support Desk
产品级验收参见[示例](/docs/zh/examples)。

## 边界

- 蓝图创建源码与本地组合，不执行部署。
- `lenso.app.json` 是精确的应用组合与锁。
- Module 在 Linked 和 Service-backed 交付间保持稳定业务身份。
- Provider Service 仍由 Host 管理；Autonomous Service 使用独立的 Rust
  `lenso.service.v2` 运行时。
- 生产发布、提升、回滚和基础设施仍由外部交付系统负责。
