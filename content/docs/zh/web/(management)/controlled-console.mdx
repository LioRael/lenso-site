普通 Native Management 源码 App、MCP 写入和真实浏览器旅程已保留审批后业务更新与
持久 Audit 回执。联合 Agent 与六个安装/移除 Profile 也有独立回执。本篇最新 SDK
源码候选教程使用下方固定的 Examples 源码及[资格索引](https://github.com/LioRael/lenso-examples/tree/027f01bb366f8b8eeaa9b5a0886c0d4bcddba740/fixtures/ops-reference/qualification/README.md)；历史 live 回执不能证明当前
候选已发布到 registry。
新 Core `119b` Human 旅程通过 23 个向量；独立 Agent 旅程通过 14 个向量和同一 App
上的六个并发 Console Session 探针，使用单独记录的 Agent `bec995` 产物。
这些探针不替代历史浏览器旅程，也不代表新浏览器验收。

## 准备源码 App 及其回执

进入选定 [Lenso Examples](https://github.com/LioRael/lenso-examples/tree/027f01bb366f8b8eeaa9b5a0886c0d4bcddba740/fixtures/ops-reference) checkout 的
`fixtures/ops-reference`，用 `python3 prepare.py --cache candidate-tools`
构建精确 CLI。使用 `candidate-tools/tools.json` 中的可执行文件，以及已授权、
私有保存的测试数据库 URI 文件：

```sh
python3 verify_management.py --cli /absolute/path/from/tools.json/lenso \
  --database-url-file /private/path/test-postgres-uri \
  --audit-url-file /private/path/test-audit-postgres-uri \
  --receipt management-receipt.json
```

候选装配使用普通 CLI Discovery 和保存的具名依赖选择；最终构建前移除 Bootstrap。
Verifier 启动前删除源码，再检查准入、审批、领域回执、Audit 来源和重启。它保留
自有目录供检查；响应不确定时不要重复 Bootstrap。

按 [operators 认证旅程](/docs/zh/web/operators-auth) 增加 Browser-ready 选项，
取得真实人类 Console 回执。用不同浏览器 Context 请求、审批同一不可变 Intent，
然后查看提交结果。PAT Secret 在 Hide 或 Unmount 后必须消失，不能进入浏览器
持久存储。

安装与移除验证复用已完成的 API、人类和真实委派 Agent 回执：

```sh
python3 verify_installations.py --cli /absolute/path/from/tools.json/lenso \
  --api-root /private/path/completed-api-profile \
  --human-root /private/path/completed-human-profile \
  --api-receipt management-receipt.json --human-receipt human-receipt.json \
  --agent-receipt agent-receipt.json --receipt installations-receipt.json
```

Installation Verifier 不接受假传输凭证作为 Agent 证明。它检查选定组合与移除，
并确认业务状态未改变。这些候选命令不代表资格已完成；发布前必须保留普通源码 App、
浏览器和共同运行 Agent 的回执。

## 选择可选 Surface

现有 [App Console](/docs/zh/core/app-console)描述单独验收的开发套件与 Contribution
Compiler。其中服务 Allow/Deny 是演示业务规则；添加页面不会提供生产身份认证或
管理权限。

候选装配中的业务 App 可以不启动 Console，也不启动 Agent。Console 展示 Owner
发布的管理 Entry 和审批操作，不持有业务表、登录状态、Grant 或 Decision。选择 Web
Surface 不能改变私有 Backend 选择。

## 审阅不可变操作

Guard 必须针对选中 Deployment 与 Entry 完成：

1. 验证 operators Assertion 与当前 CredentialState；
2. 对 Credential Ceiling、当前 RBAC 和 Host 准入的 Entry Policy 取交集，包含目标 Resource Scope；
3. 发布精确版本的输入 Schema，创建带 Operation ID 与预期 Resource Revision 的不可变写入 Intent；
4. 通过当前有效的人类 Route，由 Approval 决定精确 Intent；自报 Caller、Approver 或 Assurance 不授权；
5. 执行时重新检查权限，调用业务 Owner 的生成 Port，保留领域回执与带来源的 Management Audit。

Target、Schema、参数、Scope 或 Revision 改变会使已审批 Intent 失效。取消、拒绝和
过期决定不执行。复杂领域页面仍需编写 Contribution；Catalog 不会生成完整业务 UI。

## 恢复 Unknown Invocation

派发后响应中断可能留下 `unknown` 结果。Console 必须保留 Invocation Identity，
展示状态，并向同一业务 Owner 请求回执对账，不能标为失败或自动重新提交。
持久领域回执与 Audit 来源是不同事实，页面不能伪造其中任何一种。

普通 Native 回执证明各自记录的源码 App、独立 Realm 准入、审批写入、来源、重启与
浏览器恢复边界。联合 Agent 及关闭 Console 的安装证据分别保留。历史 Workers D1
管理 Profile 另有本地与远端回执；这些结果不能继承 Native 浏览器结果，也不能证明
当前最新 SDK 源码配对通过了相同验收。

保存回执后按 Owner 步骤停止 Host 并清理测试资源。关闭 Console 移除可选体验，
不删除业务 Plugin、其状态或独立授权规则。
