---
title: 编写 Rust Module
description: 通过 Lenso 公共 Rust 门面实现原生 Module。
---

原生 Module 应该呈现业务行为，而不是运行时接线。公共门面会根据 Module
源码派生 Descriptor、Adapter Factory、Endpoint 注册和配置解码。

## 创建 Module

```sh
lenso new greeting --runtime rust
cd greeting
lenso check
lenso dev
lenso verify
```

脚手架包含 Capability Contract、原生 Module、开发 Runner、Lock 和验证用例。
相关源码变化后，`lenso dev` 会重新构建选中的 Package、解析新的 App Plan，
并重启 Runner。

可使用 `--recipe stateless`、`stateful`、`web-console` 或 `managed-work`
生成聚焦的 Module Card。Card 记录设计意图，运行时元数据仍由源码派生。

## 实现业务行为

假设 [编写 Capability](/docs/zh/capability-authoring) 已生成
`greeting_contract` crate：

```rust title="src/lib.rs"
use greeting_contract as greeting;
use lenso::prelude::*;

#[module]
#[derive(Clone, Debug)]
struct Greeter;

#[provides(greeting::Greeting)]
impl Greeter {
    async fn greet(
        &self,
        _context: Ctx,
        request: greeting::GreetRequest,
    ) -> Result<greeting::GreetResponse, greeting::GreetError> {
        if request.name.trim().is_empty() {
            Err(greeting::GreetError::EmptyName)
        } else {
            Ok(greeting::GreetResponse {
                message: format!("Hello, {}!", request.name),
            })
        }
    }
}
```

方法直接返回生成的 Domain Result。Adapter Failure 由生成的 Lowering 在运行时
处理。作者无需手写 `NativeModuleFactory`，也无需逐个注册 Endpoint。

## 仅在需要时添加配置

```rust title="src/lib.rs"
#[derive(Clone, Debug, serde::Deserialize)]
#[serde(deny_unknown_fields)]
struct GreetingConfig {
    prefix: String,
}

#[module]
#[derive(Clone, Debug)]
struct Greeter {
    #[config]
    config: GreetingConfig,
}
```

无状态 Module 不写 `#[config]`。生成的 Factory 会在创建 Module 时解码并验证
所选 Instance 的配置。

## 仅在需要时添加生命周期和依赖

只提供 Endpoint 的 Module 无需实现生命周期。拥有资源或托管任务的 Module
需要显式选择加入：

```rust title="src/lib.rs"
#[module(lifecycle)]
#[derive(Clone, Debug)]
struct Worker {
    greeting: Port<greeting::GreetingClient>,
}

impl Lifecycle for Worker {
    async fn activate(
        &self,
        context: ActivateContext,
    ) -> Result<(), RuntimeFailure> {
        // 通过 context.tasks() 启动 Module 自己拥有的任务。
        Ok(())
    }

    async fn deactivate(
        &self,
        context: DeactivateContext,
    ) -> Result<(), RuntimeFailure> {
        // 在这里关闭 Module 自己拥有的资源。
        Ok(())
    }
}
```

生成的 Glue 会根据 App Plan 中的显式 Binding 连接 `Port<Client>` 字段；系统中
不存在全局 Capability Registry。

## 链接到产品 Runner

产品 App Binary 只需一次性暴露所有编译进来的 Module Factory：

```rust
let native = NativeModuleRegistry::new().with_linked_factories();
let adapters = ExecutionAdapterCatalog::single(native);
```

静态链接只表示 Factory 可用，并不会激活 Module。App Definition 仍负责选择
Instance 和 Binding，产品自己的 Host 运行解析后的不可变 Plan。继续阅读
[Module 组合](/docs/zh/module-composition)。

## 检查并证明可删除

`lenso check` 快速检查源码、Contract、配置和 Package Lock；`lenso verify`
运行声明的成功、Domain Error、Runtime Failure、Lifecycle 和删除验证，并将结果
写入 `.lenso/module-verification.json`，供 CI 与 Agent 使用。
