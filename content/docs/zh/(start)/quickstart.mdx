title: 快速开始
description: 创建、运行、打包并安装一个强类型 Lenso Plugin。
---

当前最短的受支持路径从一个普通 Plugin 项目开始。Rust 可由同一份源码生成
可移植 Wasm 与可信 Process 实现；Bun 使用生成的 `@lenso/bun` Runtime Lowering。

## 前置条件

- `lenso` CLI；
- 默认脚手架需要 Rust Stable 与 `wasm32-unknown-unknown` Target；
- 只有选择 `--runtime bun` 时才需要 Bun 1.2.21 或更新版本。

## 创建并运行 Plugin

```sh
lenso plugin new example.echo
cd example.echo
lenso plugin check
lenso plugin dev \
  --operation execute \
  --request-json '{"name":"example.echo","arguments_json":"{\"text\":\"hello\"}"}'
lenso plugin pack
```

`lenso plugin dev --watch` 会在源码变化后重新构建并调用。开发构建保持未优化；
`plugin pack` 执行 Release 构建，并用安装时相同的验证器重新打开生成的
`.lenso-plugin` Archive。

TypeScript 使用等价的 Bun 脚手架：

```sh
lenso plugin new example.echo --runtime bun
```

只编辑 `src/plugin.ts`。生成的 Entrypoint 持有 Descriptor 投影、开发调用与
正式 Bun Server；业务代码不实现 JSON-RPC 或进程生命周期。

## 创建 App Workspace

App 由一个精确 Host Build 与可见 `plugins/` 目录派生。使用匹配的 Host Artifact
初始化目录：

```sh
lenso app init \
  --host /path/to/host \
  --host-catalog /path/to/host-catalog.json \
  --root ./my-app
cd my-app
lenso app check
lenso app show
```

本地 Bundle 使用 `lenso plugins add`；Catalog 安装必须指定精确版本：

```sh
lenso plugins search echo
lenso plugins install example.echo --version 1.0.0
lenso plugins configure example.echo default --file echo.toml
lenso app check
lenso run
```

Catalog 安装会校验下载 Archive Digest、Manifest Digest、Bundle Closure、Host
Target、Execution Class 与 Candidate App，之后才替换 Desired State。更新时保留
精确 Archive，可通过 `plugins history` 与 `plugins rollback` 回滚。

设置或解析失败时运行 `lenso doctor`；默认输出适合人阅读，`--json` 输出稳定结构。
