Lenso 是面向 Rust 业务系统的 Agent-ready 模块化应用与微服务框架。
先建立一个明确的应用组合，把业务能力保留为 Linked Module 或
Provider-backed Module；只有边界需要独立所有权时，才迁移为
Autonomous Service。

公开开发生命周期只有四步。

## Compose（组合）

从产品蓝图生成唯一的 `lenso.app.json`：

```sh
lenso app compose ./support-desk --blueprint support-desk --apply
```

Bare Blueprint 选择 `auth`、`notification-worker` 与 `support-api`。生成文件
绑定应用修订、制品摘要、依赖选择，以及 Linked 或 Service-backed Module
实现。它就是应用组合与锁；不要手工把进程命令复制进去。Support Ticket 与
Story 产品链由 Pack-backed [Support Desk 验收](/docs/zh/examples)覆盖。

## Run locally（本地运行）

通过公开 CLI 启动生成的 Host、auto-start Provider Service 与已连接的本地
Console：

```sh
cd support-desk
lenso dev up --console-root ../lenso-console
```

该命令会创建仅限 loopback 的已签名 Enrollment Material、协调 Module 自有
UI Artifact，并在报告 System Ready 前连接精确拓扑。本地开发不需要
Kubernetes。生产发布和部署由外部交付系统持有，不属于 Console 权限。

## Connect（连接）

`lenso dev up --console-root` 写入 `.lenso/console-connect.json`，再通过经过
认证的 Console Connection Boundary 应用该精确 Bundle。Bundle 包含已签名的
本地 Service Enrollment、Topology Digest、Management Binding，以及可选的
Console Artifact Effect。Console 记录连接并加载与回执绑定的
`console_ui_esm` Module Surface；它不会创建、部署、接管、删除、发布或修复
Workload。

服务端连接边界和浏览器流程请继续阅读
[Lenso Console](/docs/zh/runtime-console)。

## Status（状态）

在 Console 中读取已连接的 System。System、Service、Module、Surface 与
Adapter Projection 显示 `connected`、`unavailable`、`incompatible` 或
`unmanaged`，需要处理时会给出直接原因。Workload Operational State 是独立
维度；控制 Adapter 不可用时，Workload Observation 为 `unknown`，变更会被
拒绝且不排队、不回退。

## 核心边界

- **Module 保持业务身份。** 能力可以 Linked 交付，也可以由 Service 提供，
  不需要改名。
- **Business API 保持强类型。** Module Surface 使用生成客户端和精确的
  Surface Grant 调用声明的操作。
- **Console 是 System Plane。** 它报告当前状态并调用目标持有的受支持操作，
  不是部署平面。
- **Rust 支持两个服务层级。** TypeScript 当前只支持 Provider 开发；详见
  [Service Capability Tiers](/docs/zh/autonomous-services)。
- **只拆分稳定边界。** Autonomous Service 持有自己的运行时、存储、身份与
  运维，不是默认起点。

## 安装

- Rust Module 与 Host 声明使用当前 `lenso` facade。
- `@lenso/cli` 与 `lenso-cli` 都提供 `lenso` 命令。
- TypeScript Provider 使用 `@lenso/service-kit`。
- Lenso Console 使用 `lenso console install` 独立安装。
