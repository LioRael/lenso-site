远程模块使用与链接模块相同的主机拥有的合约，但运行在
他们自己的流程或服务。

对于新的进程外业务模块，更喜欢服务支持的模块
发布路径在【模块安装](/docs/zh/module-installation).本页
记录旧版远程模块协议和兼容性套件。

当模块需要单独的运行时、进程、
部署节奏或信任边界。保留普通的第一方业务逻辑
链接直到这些原因之一存在。

## 本地创作循环

```sh
lenso module create billing --remote --output-dir ../module-packages
cd ../module-packages/billing
pnpm install
pnpm dev
```

然后将运行模块安装到主机中。

## 安装 Manifest

```sh
lenso module install http://127.0.0.1:4110/lenso/module/v1/manifest
```

远程模块声明它们的源、路由、运行时函数、管理界面、
以及通过Manifest进行可选的 Runtime Console捆绑。主机拥有加载，
代理、回执和操作员可见性。

安装后，重新启动API和worker，以便主机重新加载远程
源列表。

## JavaScript 和 TypeScript 套件

远程模块作者使用：

```sh
pnpm add @lenso/remote-module-kit@0.1.3
```

该套件位于Runtime Console存储库中，是
进程外模块创作。

如果您需要实现另一个运行时，请阅读
[HTTP JSON 和 gRPC 线路的远程模块协议](/docs/zh/remote-protocol)
合约。

## 远程模块代码

生成的远程后端是一个 Node 服务器。一个小模块如下所示：

```js
import {
  defineRemoteModule,
  defineSchemaEntity,
  getRoute,
  runtimeFunction,
  schemaAdmin,
  serveRemoteModule,
  textField,
  timestampField,
} from "@lenso/remote-module-kit";

const contacts = [
  {
    id: "contact_1",
    email: "ada@example.com",
    name: "Ada Lovelace",
    created_at: "2026-01-01T00:00:00Z",
  },
];

const contactsEntity = defineSchemaEntity({
  name: "contacts",
  label: "Contacts",
  readCapability: "crm.contacts.read",
  fields: [textField("email"), textField("name"), timestampField("created_at")],
});

const module = defineRemoteModule({
  name: "crm",
  version: "0.1.0",
  capabilities: ["crm.contacts.read"],
  admin: schemaAdmin([contactsEntity]),
  httpRoutes: [
    getRoute("/contacts/{id}", {
      capability: "crm.contacts.read",
      displayName: "Fetch Contact",
      storyTitle: "Fetch Contact",
    }),
  ],
  runtimeFunctions: [
    runtimeFunction("crm.contacts.enrich.v1", {
      version: 1,
      queue: "crm",
      inputSchema: "crm.contacts.enrich.v1",
    }),
  ],
});

await serveRemoteModule(module, {
  data: {
    contacts: {
      list: async ({ limit }) => ({
        records: contacts.slice(0, limit),
        next_cursor: null,
      }),
      detail: async (id) => contacts.find((contact) => contact.id === id),
    },
  },
  http: {
    "GET /contacts/{id}": ({ params }) =>
      contacts.find((contact) => contact.id === params.id) ?? null,
  },
  runtime: {
    "crm.contacts.enrich.v1": ({ input }) => ({
      contact_id: input?.contact_id,
      status: "queued",
    }),
  },
});
```

主机安装 Manifest URL 并保留身份验证、代理、运行时回执、
以及主机端的控制台可见性。

## 主机仍然拥有什么

远程并不意味着不受管理。主机仍拥有：

- Manifest加载和 lint 结果
- 代理远程 HTTP 路由
- 运行时函数回执
- 安装回执和本地服务状态
- Runtime Console可见性

## 局部诊断

对于长时间运行的远程模块服务：

```sh
lenso module doctor
lenso module doctor billing
```

Doctor检查已安装的模块服务状态、就绪 URL 和过时的锁或
pid 文件。
