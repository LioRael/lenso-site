---
title: 远程模块协议
description: 实现进程外 Lenso 模块使用的 HTTP JSON 或 gRPC 协议。
---

远程模块公开主机拥有的协议。远程进程实现
模块行为； Lenso 主机拥有身份验证检查、代理命名空间、运行时
回执、重试、安装状态和 Runtime Console 证据。

大多数 TypeScript 模块应使用 `@lenso/remote-module-kit`。此页面适用于
需要了解 Wire 合约或实现另一个运行时的作者。

## 传输方式

主机从配置的基本 URL 中选择传输。

|基本网址 |交通 |
| --- | --- |
| `http://.../lenso/module/v1` | HTTP JSON |
| `https://.../lenso/module/v1` | HTTP JSON |
| `grpc://host:port` | gRPC JSON 信封 |
| `grpcs://host:port` |基于 TLS 的 gRPC JSON 信封 |

主机修剪尾随斜杠。 HTTP JSON 路径是相对于基本 URL 的。
gRPC 使用带有 `JsonEnvelope` 有效负载的服务 `lenso.remote.v1.RemoteModule`。

## Host 与远程模块之间的身份验证

配置主机到远程令牌：

```sh
REMOTE_MODULE_BILLING_TOKEN=secret-host-to-module-token
```

对于 HTTP JSON，主机将其作为Bearer Token发送。对于 gRPC，主机发送
通过远程传输层的元数据。

主机不会将调用者的Bearer Token或 cookie 转发到远程
模块。调用者身份在请求有效负载中表示为有界参与者
语境。

## Manifest

HTTP JSON：

```text
GET /manifest
```

远程过程调用：

```text
RemoteModule.GetManifest(JsonEnvelope) -> JsonEnvelope
```

响应是序列化的 `ModuleManifest`。主机验证Manifest
名称与配置的模块名称相对应，并拒绝远程 HTTP 路由路径
不是模块本地的。

有效的远程 HTTP 路由路径必须：

- 以 `/` 开头；
- 避免使用 `//`、`://`、查询字符串和片段；
- 避免空、`.` 或 `..` 路径段。

## 管理数据和查询

HTTP JSON 端点：

```text
GET /admin/{entity}?limit=50&cursor=...
GET /admin/{entity}/{id}
GET /admin/queries/{query}
```

响应形态：

```json
{ "records": [{ "id": "contact_1" }], "next_cursor": null }
```

```json
{ "record": { "id": "contact_1" } }
```

```json
{ "data": { "total": 12 } }
```

gRPC 方法：

```text
ListAdminRecords
GetAdminRecord
QueryAdminValue
```

## 管理员操作

HTTP JSON：

```text
POST /admin/actions/{action}
```

请求正文是任意 JSON 操作输入。回复：

```json
{ "result": { "status": "ok" } }
```

gRPC方法：

```text
InvokeAdminAction
```

动作名称必须是稳定的路径段：ASCII 字母、数字、`.`、`_`、
和`-`。

## HTTP 路由代理

Manifest中的远程路由元数据成为主机可见的代理路由：

```text
/modules/{module}/http/{*path}
```

主机将传入路径与Manifest声明的模块本地路由相匹配
并将有界请求转发到远程模块。

HTTP JSON 遥控器在其声明的路由路径上接收正常的 HTTP 请求。
gRPC 远程接收：

```text
ProxyHttpRoute
```

请求信封包括请求id、相关id、模块名称、方法、
声明的路径、远程路径、路径参数、允许的标头和 JSON 正文。

代理调用记录在 `platform.remote_http_proxy_calls` 中并投影
进入[Runtime Story](/docs/zh/runtime-stories)。

## 运行时函数

HTTP JSON：

```text
POST /runtime/functions/{function_name}/invoke
```

要求形态：

```json
{
  "request_id": "req_1",
  "function_run_id": "fnrun_1",
  "function_name": "billing.invoice.sync.v1",
  "attempt": 1,
  "correlation_id": "corr_1",
  "causation_id": "evt_1",
  "actor": { "kind": "system" },
  "trace": { "trace_id": "trace_1", "span_id": "span_1", "baggage": [] },
  "input": { "invoice_id": "inv_1" }
}
```

回复：

```json
{ "output": { "status": "synced" } }
```

gRPC方法：

```text
InvokeFunction
```

主机拥有函数运行行、尝试、重试策略和死信状态。
Remote模块只是执行者。

## 事件处理程序

HTTP JSON：

```text
POST /events/handlers/{handler_name}/invoke
```

该请求包括Outbox事件 ID、处理程序名称、事件名称、事件版本、
源模块、聚合、相关 ID、因果 ID、参与者、跟踪、有效负载、
和标题。

远程处理程序最多可以返回一个有界主机操作：

```json
{
  "actions": [
    {
      "type": "enqueue_function",
      "function_name": "billing.invoice.sync.v1",
      "input": { "invoice_id": "inv_1" }
    }
  ]
}
```

gRPC方法：

```text
HandleEvent
```

远程模块从不直接声明Outbox行。Host声称此次活动，
调用远程处理程序，验证返回的操作，并将运行时排入队列
如果允许就工作。

## 错误

远程模块应返回标准信封：

```json
{
  "error": {
    "code": "validation",
    "message": "missing invoice_id",
    "retryable": false,
    "details": [
      { "field": "invoice_id", "reason": "required" }
    ]
  }
}
```

仅在暂时依赖失败时使用 `retryable: true`。验证错误
不应重试。

## 本地实施建议

除非您需要另一个运行时，否则请使用该套件：

```sh
pnpm add @lenso/remote-module-kit@0.1.3
```

然后验证主机路径：

```sh
lenso module install http://127.0.0.1:4110/lenso/module/v1/manifest
lenso module doctor
```

打开 `/console` 并检查模块、数据、操作、运行时和Story。
