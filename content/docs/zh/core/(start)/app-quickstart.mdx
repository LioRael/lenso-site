---
title: 创建本地 Web App
description: 用源码构建的 CLI 预览 App 工作流，并在浏览器中完成一次真实问候。
---

> **本地候选预览。** 当前 `lenso-cli` 源码已实现 `app create --web`，但本页不声称
> npm/Cargo 已发布包含该命令的版本，也不声称生成项目的全部依赖均已发布。请使用
> 匹配源码构建的 CLI。若依赖不可用，应停下并记录精确版本；生成源码不等于独立构建成功。

这条路径创建一个 App 自有的 Web Plugin，启动生成的 Host，再从浏览器表单发出真正的
`POST /greetings` 请求。它不需要 Marketplace 条目。手工开发与 Coding Agent 使用
**同一组命令和完成检查**。

## 1. 从匹配源码构建 CLI

在当前 `LioRael/lenso` 源码 Checkout 根目录，确认已安装 Rust 与 Cargo：

```sh
cargo build --locked -p lenso-cli --bin lenso
LENSO_CLI="$(pwd)/target/debug/lenso"
"$LENSO_CLI" app create --help
```

确认帮助中出现 `--web`。`PATH` 中安装的 `lenso` 可能是旧公开版本；本页后续命令
均使用绝对路径 `LENSO_CLI`。创建时脚手架会运行 Cargo check，因此要继续预览，
它锁定的依赖必须可用。

## 2. 创建并运行同一个 App

继续使用上面的 Shell。临时父目录让预览留在框架 Checkout 之外；要长期保存 App，
可改用自己选择的空父目录。

```sh
APP_PARENT="$(mktemp -d)"
"$LENSO_CLI" app create "$APP_PARENT/hello-web" --web
cd "$APP_PARENT/hello-web"
"$LENSO_CLI" app dev
```

App 包含 `app/local.starter/` Rust Plugin 和由 Plugin 持有的
`public/index.html`。生成的 Host 提供 Web Ingress；你不需要手写 Host Catalog 或
Plan。保持 `app dev` 运行，在浏览器中打开 Host 打印的精确
`Listening on http://...` 地址，不要假定固定端口。

在页面表单输入 **Ada**，点击 **Create greeting**。页面应显示来自 Plugin
`POST /greetings` Endpoint 的 **Hello, Ada!**。若未出现，检查浏览器控制台与
网络响应。仅看到 HTML 页面不算完成，POST 必须成功。

## 3. 构建并检查结果

停止 `app dev` 后，从 `hello-web/` 执行：

```sh
"$LENSO_CLI" app build --out dist-review
"$LENSO_CLI" app check --root dist-review
"$LENSO_CLI" app show --root dist-review --json
"$LENSO_CLI" app start --from dist-review --check
```

`app build` 不覆盖已有输出目录。check/show 检查构建后分发目录的 Plugin Root
和解析结果；`start --check` 完成激活并关闭。源码构建成功仍不等于有公开可下载
Release 或已部署。

## 让 Coding Agent 执行相同步骤

向 Agent 提供匹配源码 Checkout 和一个本地空父目录，然后使用以下有边界的请求：

```text
按本页手工命令创建本地 Web App，使用这个 Checkout 源码构建的 lenso CLI。
App 放在框架源码树外。运行 app create hello-web --web 和 app dev。
在真实浏览器提交 Ada，展示 Hello, Ada! 结果与控制台错误。
停止 dev 后，对同一个 App 运行 app build、app check、app show 和
app start --check。报告精确 CLI Revision、命令、输出路径、浏览器 URL 与失败。
若锁定的依赖组不可用，应停止并报告边界；不要换用其他 Release 或声称成功。
```

Agent 可以编辑 `app/local.starter/` 中的普通业务代码，但 App 选择与 Authority
仍来自 App 的 `plugins/` Root 和 Host。Site 不能操作你的本地文件，也不能替你
批准安装。

## 仅在真实可用时采用其他 Plugin

[浏览 Plugin](/plugins)，查看分发方式、版本、Target 与文档。候选
`lenso.web-ingress` 页面**不是**已签名 Catalog Release，不能当作安装说明。
即使看到已签名的 Linked Cargo 列表，CLI 仍须校验精确 Snapshot、公钥信任、
`.crate`、Host Target、构建和解析后的 App，才能确认采用。完成本地问候无需
采用目录 Plugin。

已发布 CLI 的独立 Plugin 工作流仍见[Plugin 快速开始](/docs/zh/core/quickstart)。
本地 App 的发现与打包原理见[本地 App 开发](/docs/zh/core/engine-dx)。
