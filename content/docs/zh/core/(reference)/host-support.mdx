构建 App 前先选择 Host profile。目标编译成功不能证明数据库可连接、部署平台已支持，
也不能授予管理操作权限。每个结果都应绑定到对应源码和产物。

## 分别验证各个边界

| Profile 或组合 | 已观察的边界 | 仍需区分的边界 |
| --- | --- | --- |
| 普通 Native 源码 App，模拟 state | HTTP 图、两个具名依赖、配置后的 Instance、CAS 与 receipt | Instance 重建后模拟状态重置。 |
| 普通 Native 源码 App，PostgreSQL owner | 真实 PG、两个 schema、持久 receipt 与 Host 重启 | Operator setup 与 DB 权限仍需显式提供。 |
| 普通 Native operators Management 与 Console | API Token/MCP 读写、真实 Account/PAT 浏览器旅程、持久 Owner Audit 与重启 | 记录的是历史源码 Profile；最新 SDK 源码配对另有检查。 |
| 独立 Native 管理 Agent | Account 签发 child、确定性 Model/Loop/Session、精确任务绑定、原 pending 状态恢复与父凭证实时撤销 | 真实模型交互按 Owner 要求为 `not_run`。 |
| Native 安装与移除 | 六个选定组合、可选 Console/Agent 与移除检查 | 只证明回执中的选择，不推导通用安装 Profile。 |
| 静态 linked Rust Workers 候选 | Wasm 构建与真实本地 workerd HTTP 路由 | 仅支持 request 图；Plugin 内存属于单次事件。 |
| 纯业务 Workers 候选及 owner D1 facility | 本地 D1 模拟与部署后的真实 D1 分别记录 receipt | 这份业务证明不代表 Hyperdrive 或 Management guard 已通过。 |
| Workers 经 Hyperdrive/PG | `not_run`；owner 暂缓验收 | 不声明远端 PG 已通过。 |
| 一个 Worker 混用 PG 与 D1 | `unassessed` | 需一起验证实际 driver、binding 和 scope 生命周期。 |
| 普通 Workers Auth/Management D1 源码 Profile | 实际远端 Core `119b` / Console `ed1` 图；直接调用和官方 MCP Client、审批、丢响应后的状态恢复、类型化 Audit、实时撤销、只读 Profile 与 readiness 故障 | 只证明回执中选定的 Owner 与产物；观察 redeploy 不证明物理重启。Workers Agent 与人类 Cookie/PAT 旅程另行验收。 |

Operations reference 使用正常源码 App、类型化 Capability client 和 Kernel 路由。
源码可移植不代表 Workers 支持所有 execution class。这个 profile 会拒绝未支持的
stream、event、动态装载和 restart policy。Bun authoring 仍是独立环境。

Owner 在 [Lenso Examples](https://github.com/LioRael/lenso-examples) 中维护可执行指南、
源码输入和 receipt。选定的最新 SDK 源码仍是候选，归档与 live
证明保留各自的身份。六篇新任务教程在当前消费与发布 Gate 完成前不进入发布目录。

## 配置与 readiness

离线 `app explain --json` 检查持久化的 target、选定 Instance、具名 provider 和已授权
facility 名称，不构造 owner handle，也不查询数据库。它不会验证凭证或证明 live readiness。
`--host-facilities` 与 `--workers-facilities` 是 Host 输入，与业务配置及
Capability 选择分开处理。

Owner 校验自己的 facility 配置，并在 App Ready 前准备选定后端。启动不执行 DDL 或
迁移数据。Operator setup 必须显式进行；更换 binding 不会搬运业务状态。保存的选择
失效时应拒绝，而不是选择新资源列表的第一项。只有 owner 接受显式 `none` 依赖选择时，
可选 cache 才为空；不能根据注册顺序推断。

Facility 选择限定可信 owner 获得哪些输入，不会沙箱化 Native 代码或替代数据库权限。
Hyperdrive 提供到 PostgreSQL 的连接路径。KV 只适合 owner 允许陈旧的数据，不能替代
权威会话撤销或原子 challenge 消费。

## 恢复不确定的写入

提交可能成功但响应丢失时，保留原 idempotency key，查询 owner receipt。取消或连接
断开不能证明回滚。不要再次执行写入来探测结果；receipt 与当前状态决定下一步操作。

身份、审批和调用状态见[管理术语](/docs/zh/core/management-glossary)；现有已发布入口见
[受支持的工作流](/docs/zh/core/supported-workflows)。
