This is the shortest public executable path into current Lenso. In about ten
minutes you will have a typed Request Capability, a Bun Provider, an explicit
`lenso.json`, canonical Plan output, and a Module running through the production
Bun Execution Adapter.

:::note
The starter is a complete Module authoring project, not a generator for an
entire production application, deployment environment, or UI.
:::

## Prerequisites

- Bun 1.2.21 or newer
- Node.js 18 or newer for the npm CLI, or Rust stable with Cargo

Confirm the tools before creating files:

```sh
bun --version
node --version
```

## 1. Install the CLI

Choose one installation path:

```sh
npm install -g @lenso/cli
lenso --version
```

Or install the same binary with Cargo:

```sh
cargo install lenso-cli --locked
lenso --version
```

This step is complete when `lenso --version` exits successfully. If an older
binary is already on `PATH`, use `command -v lenso` to identify it before
debugging the project.

## 2. Generate a typed Module project

```sh
lenso module create greeting --runtime bun
cd greeting
```

The command stages the project, installs dependencies, type-checks generated
bindings, and publishes the directory atomically. It never replaces an
existing target.

Inspect the important files:

```text
greeting/
├── lenso.json
├── package.json
├── bun.lock
├── contracts/greeting/
│   ├── capability.json
│   ├── schemas/
│   └── generated/
└── modules/greeting/
    ├── package.json
    └── src/index.ts
```

| Path | Authority |
| --- | --- |
| `contracts/greeting/capability.json` | Capability identity and Operations |
| `contracts/greeting/schemas/` | Portable request, response, and Domain Error shapes |
| `contracts/greeting/generated/` | Derived Rust and TypeScript bindings; commit them, edit the source instead |
| `modules/greeting/src/index.ts` | Product behavior implementing the generated Provider |
| `lenso.json` | Reviewable package, Instance, endpoint, contract, and execution input |
| `bun.lock` | Ordinary package-manager lock state |

## 3. Make one typed change

Open `modules/greeting/src/index.ts`. The generated Provider returns its input.
Change only the response value:

```ts title="modules/greeting/src/index.ts"
async execute(_context, request) {
  return {
    ok: true,
    value: { output: `Hello, ${request.input}!` },
  };
}
```

The generated `Provider` type is the contract boundary. A misspelled field or
wrong result shape should fail the next type check rather than becoming a wire
error at runtime.

## 4. Run the repeatable gates

```sh
bun run typecheck
bun run check
bun run resolve
```

These commands prove different things:

| Command | Completion criterion |
| --- | --- |
| `typecheck` | Module code implements the generated TypeScript surface. |
| `check` | Packages, locks, entrypoint, contract freshness, endpoints, and execution class are valid. |
| `resolve` | The project materializes canonical immutable Plan bytes under `.lenso/`. |

Inspect `git diff --no-index /dev/null .lenso/resolved-plan.json` when the file
is new, or the normal diff once it is tracked by your workflow. Confirm the
package, Instance key, entrypoint, Capability, Operation, and
`lenso.bun-process@1` execution class match the project you just inspected.

## 5. Start the Adapter development loop

```sh
lenso module dev --bun
```

The command checks the project, resolves a fresh Plan, and starts the generated
Provider through the production Bun child-process Adapter. Keep it running,
edit `src/index.ts`, and save. A valid change stops the old generation cleanly
and starts a new one; a type, contract, or startup failure leaves the watcher
alive so you can fix it. Press Ctrl-C to exercise cooperative shutdown.

The loop is ready when the Plan and Adapter start without an authoring or
activation diagnostic and the process remains in the foreground. This proves
the authoring-to-runtime path; product acceptance still requires a real
consumer request, which you add in [Build a feature](/build-a-feature).

## If something fails

- **Scaffold fails before publishing:** fix the reported Bun, package, or type
  error and rerun; the target should not contain a partial project.
- **`check` reports stale generated files:** change the Descriptor/Schema
  source and regenerate rather than editing `generated/` directly.
- **Unsupported Stream or Event in Bun code:** the public Bun SDK currently
  exposes Request Providers only. Use native Rust or extend the published SDK
  through its owning Adapter workflow.
- **Watcher reports startup failure:** keep it running, fix the first
  diagnostic, and save again. See [Troubleshooting](/troubleshooting).
