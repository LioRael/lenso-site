---
title: Quickstart
description: Install the Lenso CLI, scaffold a typed Bun Module, and run its production Adapter development loop.
---

The fastest executable Lenso path is a generated Bun Module project. It uses
the same Capability Descriptor, immutable Resolved App Plan, and portable
Kernel contracts as native Rust, while keeping process and wire mechanics in a
separate Execution Adapter.

## Prerequisites

- Bun 1.2.21 or newer
- Node.js 18 or newer for the npm-distributed CLI, or Rust stable with Cargo

## 1. Install the Lenso CLI

```sh
npm install -g @lenso/cli
lenso --version
```

The npm package contains the platform-specific `lenso` binary. Rust users can
install the same CLI from crates.io instead:

```sh
cargo install lenso-cli --locked
```

## 2. Create a Bun Module

```sh
lenso module create greeting --runtime bun
cd greeting
```

The command generates a complete project: a Capability Descriptor and schemas,
checked-in Rust and TypeScript bindings, a typed Provider, `lenso.json`, Bun
workspace manifests, and `bun.lock`. It runs installation and type checking
before atomically publishing the new directory, so a failed scaffold does not
leave a partial project.

## 3. Run the development loop

```sh
lenso module dev
```

The CLI validates the project, resolves a fresh immutable Plan, and starts the
Module through the production Bun Execution Adapter. Source and project changes
cleanly stop the old child and resolve a new generation. Type, contract, and
startup failures keep the watcher alive; fix the file and save again. Ctrl-C
performs cooperative shutdown.

Edit `modules/greeting/src/index.ts` to change the generated Provider. The
Module uses `@lenso/bun-module`; application code never implements the
JSON-RPC handshake, framing, cancellation, or process lifecycle.

## 4. Run the repeatable checks

```sh
bun run typecheck
bun run check
bun run resolve
```

`check` validates project inputs, package locks, endpoints, and generated
contracts. `resolve` writes canonical Plan bytes. The running Kernel loads that
exact Plan; it does not discover Modules, install packages, or mutate the graph.

:::note
This is a complete Bun Module authoring and development starter, not a generator
for an entire production application or deployment environment. Native Rust
Modules remain statically linked and register `NativeModuleFactory` values in
their App binary.
:::

Continue with [Bun Module authoring](/docs/bun-module-authoring) for the project
layout, Provider API, CLI options, and current Request-only SDK boundary. Read
[Project and Plan](/docs/project-and-plan) for the language-independent
composition model.

## Verify the portable core

Framework contributors can run the core repository gates independently of the
Bun host path:

```sh
git clone https://github.com/LioRael/lenso.git
cd lenso
cargo fmt --all -- --check
cargo xtask check-core-repository-boundary
cargo check --locked --workspace --all-targets
cargo test --locked --workspace
```

CI also compile-checks the portable core for `wasm32-unknown-unknown` and
`wasm32-wasip2`. Those host profiles do not automatically gain the Bun
child-process Adapter.
