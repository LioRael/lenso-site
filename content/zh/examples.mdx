## Notes：一个服务，多种入口

从 [Notes 组装](https://github.com/LioRael/lenso/blob/6e239c71a38279885facce133ceb847bbfe12f2f/examples/notes/src/application.ts)开始：它接收所选数据库实例、session store、方言查询与 principals，再创建确切 Auth、Notes 实例。共享服务执行对象归属策略；CLI、原生 Fetch 和 oRPC 适配同一业务操作。

按此顺序读文件：

1. contracts.ts、notes.ts：输入校验、身份 audience 与对象归属。
2. application.ts、auth.ts、application-auth.ts：选定资源与服务身份验证。
3. queries-sqlite.ts 或 queries-pg.ts：原生方言数据访问。
4. operations.ts、router.ts、web.ts：显式入口适配器。
5. server.ts、lenso.config.ts：本地宿主组装与运行时配置。

[数据库](/docs/zh/database)说明迁移归属，包括 Auth session 与旧未归属行；[Auth](/docs/zh/auth)解释登录证据与服务重新验证。不要从请求 JSON 分配 owner，也不要把 CLI 当作绕过授权的入口。

本地 SQLite 路径使用应用[配置指南](https://github.com/LioRael/lenso/blob/6e239c71a38279885facce133ceb847bbfe12f2f/examples/notes/CONFIGURATION.md)的键名与脚本。只检查必需键名，通过私有本地环境或 secret 机制提供凭据。本文档不含个人路径或有效凭据。

## Tasks：生产者与 worker 共享契约

[Tasks 示例](https://github.com/LioRael/lenso/blob/6e239c71a38279885facce133ceb847bbfe12f2f/examples/tasks/README.md)使用真实 PostgreSQL 队列。生产者接收已认证报告请求，持久归属将任务关联到 principal；worker 消费共享校验契约，通过审阅过的报告服务写入。

调用生产者或恢复操作前先读 contracts.ts、task.ts、ownership.ts、authorized-service.ts，再读 resources.ts、producer.ts、worker.ts、mcp.ts。PostgreSQL 预置与迁移是显式步骤。worker 不会把任意任务 JSON 变成经过授权的操作。

[Tasks](/docs/zh/tasks)覆盖 lease、重试、协作取消、保留与故障恢复；[MCP 与 agent](/docs/zh/agents)解释独立操作 allowlist。重试可能重复副作用，结果不确定时先查询持久状态再重放。

## Workers：D1 与 R2 上的 Notes

[Workers Notes 示例](https://github.com/LioRael/lenso/blob/6e239c71a38279885facce133ceb847bbfe12f2f/examples/workers/README.md)使用平台 binding 与请求拥有的应用图，不在 Worker 中运行 Bun CLI Engine 或 PostgreSQL task worker。greeting 计数器属于每请求内存，不是持久存储。

按 [Workers](/docs/zh/workers)、[Files](/docs/zh/files)和[部署](/docs/zh/deployment)选择 D1/R2 入口与本地 Wrangler 检查。dry-run bundle 成功不表示云资源已预置或生产可用。

## 一次修改一个边界

选择真实操作，检查共享 schema 与服务策略，修改服务或契约，运行聚焦示例测试，再验证调用它的入口。组装始终保留确切插件对象，不修改 .lenso 或 dist 产物。[测试与排错](/docs/zh/testing)提供各边界检查。
