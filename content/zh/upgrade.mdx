本站描述经过核实的 TypeScript 发布包，以 `549b9870acb6af239faf79245179a4f1f7e60cdb` 审计源码接口。它不是旧 Rust Host/Capability 运行时的兼容更新。[安装](/docs/zh/installation)记录精确发布组合与协议 peer。

## 从 TypeScript 0.1.0 到当前组合

1. 记录应用 lockfile、实际安装 exports 与运行宿主。源码版本字符串本身不足以确定接口。
2. 选择已核实发布组合：Core/Engine 与主要适配器 0.2.0，CLI 0.19.0，DB/Storage 0.1.1。保留精确版本与 lockfile，不要只把一个间接依赖换成 latest。使用源码 vendor 归档时，全部从同一固定 revision 构建。
3. 检查配置 preflight 与资源生命周期变化。源码 bindConfig 在业务 setup 前读取来源；inspect 仍执行可信模块顶层代码。
4. 将 oRPC 客户端与服务端一起升级至 2.0.0-beta.42。源码无 v1 协议兼容路径，需要检查重复 middleware 与客户端 fetch。
5. Bun HTTP 检查公开 /bun listener 与显式 ingress 策略。listener 可用不表示 loopback 示例可直接用作生产入口策略。
6. 普通单输入操作仍受支持。上下文操作声明 context: true，并通过可信每次调用 binding 提供上下文。检查可选 [Manage](/docs/zh/manage)、确认/审批 gate 和独立 CLI/MCP 选择；描述元数据不授予服务授权。
7. 运行聚焦服务/入口测试并重新生成拥有的产物。独立检查迁移历史；升级包不应用数据库迁移。

参考[配置](/docs/zh/configuration)、[Web](/docs/zh/web)、[Auth](/docs/zh/auth)与[测试](/docs/zh/testing)。选择新版源码包前核查实际 registry 产物；源码 release 提交本身不能证明 npm 可用。Manage 已实现为可选有限操作适配器，不是持久控制平台或自动 Console 集成。

## 从 Rust 一代迁移

这属于应用迁移，不是包重命名。盘点业务服务、持久数据、身份 audience、归属策略与宿主副作用，以精确依赖和 cleanup 重新组装普通 TypeScript 插件。一次移动一个入口，测试共享服务策略。不要把旧 Cargo/Host/Capability 或动态 Marketplace 命令复制到 TS 应用。

目前没有自动 Rust-to-TypeScript migrator 或数据转换工具。保留旧数据，明确审阅 schema/身份变更。现有 Notes/Tasks 案例展示新边界，不会自动迁移任意旧应用。

## 旧页面去了哪里

旧文档保留在仓库 legacy/rust-site/content，并可从[重构前源码快照](https://github.com/LioRael/lenso-site/tree/bce1f2c08d238cec9e57a4c7a0218c8413b804c5/content/docs)阅读。它们不进入当前侧栏、搜索、Markdown 目录或 sitemap，既保留历史，也不把退役契约当作当前事实。

旧文档路由跳转到同语言迁移页，解释代际变化，不声称教程一一对应。旧站/Marketplace 源码也保留在 legacy/rust-site，不参与 docs CLI 构建。此文档更新不包含 Marketplace 宿主切换、catalog 信任变更或 Console/Relay 迁移。

已有旧应用使用版本匹配归档与安装产物；新 TS 应用从[快速开始](/docs/zh/quickstart)开始。
